# Nexigon Agent and CLI 0.7.0

Released 2026-11-22.

With this release, Nexigon Agent keeps the software of a device up to date on
its own. It installs the system release that Nexigon Hub assigns to the device
through Rugix Ctrl or RAUC, and it installs, updates, and runs Rugix Apps. These
integrations replace the separate update services and command scripts that
device images previously installed. The Agent also reconnects after it loses
its connection instead of exiting, and it can keep its device key in hardware,
such as a TPM.

Nexigon CLI 0.7.0 selects an organization for each command, pages through large
device and version lists, and manages repository path names, checkpoint
releases, and release marks.

## Before Upgrading

### 1. Check Nexigon Hub and CLI Compatibility

Nexigon Hub manages the new integrations from version 2026.4.0 on. If you host
Nexigon Hub yourself, upgrade it to 2026.4.0 or later before you upgrade
Agents. CLI 0.6.1 and earlier cannot list devices on Nexigon Hub 2026.4.0, so
upgrade Nexigon CLI together with Nexigon Hub.

### 2. Switch Device Images to the Integrations

If your device images install the `nexigon-rugix-ota`, `nexigon-rauc-ota`, or
`nexigon-rugix-apps` recipes, replace them with the integrations. Devices keep
their update configuration and status, since the integrations use the same
device properties. Review that configuration before the rollout: the
integrations honor policies that the recipes ignored, such as maintenance
windows. [Upgrade to Nexigon Agent 0.7](https://docs.nexigon.dev/agent/upgrading)
shows the changes for Rugix Bakery and Yocto images and how to roll out the
first image.

### 3. Update Custom Systemd Units

Agent 0.7.0 stops gracefully on SIGTERM and interrupts an installation in
progress. The unit that earlier installers wrote allows only 5 seconds for this
and refers to a PID file that the Agent does not write. Running the installer
again replaces the unit. In units that you maintain yourself, remove `PIDFile`
and `ExecStop` and allow 30 seconds:

```ini
[Service]
Type=exec
ExecStart=/usr/bin/nexigon-agent run
TimeoutStopSec=30
KillMode=mixed
Restart=always
RestartSec=60s
LimitNOFILE=8192
```

### 4. Check Scripts That Use the Agent's Commands

The Agent's `device`, `events`, and `repositories` commands now go through the
running Agent and fail while it is not connected to Nexigon Hub. Without a
running Agent, they connect on their own as before. The local
`repositories create` command requires `--organization <org-id>`.

### 5. Select the Organization in CLI Scripts

With a user token, the resource commands of Nexigon CLI require
`--organization`. `projects create` and `repositories create` take the
organization through this option instead of as their first argument:

```shell
nexigon-cli projects create --organization <org-id> <name>
nexigon-cli repositories create --organization <org-id> <display-name>
```

Organization API tokens select their own organization, so commands that use
them need no change.

## System Updates

The system update integration installs the version of an update bundle that a
tag of a package points to. Enable it in the Agent configuration,
`/etc/nexigon/agent.toml` by default. For example, this configuration makes a
device with Rugix Ctrl follow the tag `stable` of the package `gateway-os` in
the repository `acme`:

```toml
[integrations.rugix.system-updates]
enabled = true
path = "acme/gateway-os/stable"
```

For RAUC, use `[integrations.rauc.system-updates]` instead. When the tag moves
to a new version, the Agent downloads and installs its bundle and reboots the
device. The `dev.nexigon.ota.config` property of a device or its profile can
override the path and add policies: holds, maintenance windows, retries, and
spreads, which release a new version to a fleet gradually. A version can also
name a base version, a checkpoint release that devices further behind install
first, so that they do not skip, for example, a data migration. The Agent
reports its progress in `dev.nexigon.ota.status`. See
[System Updates](https://docs.nexigon.dev/agent/concepts/system-updates).

## Rugix Apps

The Rugix Apps integration, which requires Rugix Ctrl 1.4 or later, manages the
apps listed in the `dev.nexigon.rugix-apps.config` property. Enable it in the
Agent configuration:

```toml
[integrations.rugix.apps]
enabled = true
```

The Agent installs the release of each app for the device's architecture and
starts or stops it as configured. Apps support holds, maintenance windows,
spreads, and retries. For apps that the configuration does not list, the Agent
offers commands that start, stop, roll back, and remove them. With Rugix Ctrl
1.4.1 or later, the `nexigon.rugix-apps.logs` command returns the recent logs
of an app. See
[Rugix Apps](https://docs.nexigon.dev/agent/concepts/rugix-apps).

The configuration and status properties of both integrations are stable. Later
Agent versions only add optional fields, so a device that rolls back to an
older system image can still read a status that a newer Agent wrote.

## Reconnection

The Agent reconnects to Nexigon Hub after it loses its connection, with a
random delay of up to 10 minutes between attempts, so that a fleet does not
reconnect all at once after Nexigon Hub restarts. The integrations keep running
while the Agent is disconnected. `nexigon-agent status` prints the connection
state of the running Agent. See
[Connection](https://docs.nexigon.dev/agent/concepts/connection).

## Hardware-Held Device Keys

The Agent can authenticate with a device key held by a TPM, a PKCS#11 token, or
the Raspberry Pi firmware instead of a key file. A signer script, configured in
the new `[signer]` section, provides the public key and signs the device
certificate and each TLS handshake. See
[Identity](https://docs.nexigon.dev/agent/concepts/identity).

## CLI

Besides organization selection, Nexigon CLI 0.7.0 adds these commands and
options:

- `auth status` prints the user or organization that the token authenticates.
- `projects devices list` and `repositories packages versions list` return
  pages, newest first, which `--limit` and `--cursor` select. Version lists
  also take `--search`.
- `repositories set-path-name` sets the name of a repository in paths, such as
  `acme` in `acme/gateway-os/stable`.
- `repositories versions set-base` defines checkpoint releases.
- `repositories versions mark-release` protects a version from deletion and
  package retention.
