# Nexigon Agent and CLI 0.7.0

## Highlights

Agent 0.7.0 updates the software on devices. With Rugix Ctrl or RAUC, it
installs the system release that Nexigon Hub assigns to a device and supports
holds, maintenance windows, spreads, retries, and checkpoint releases. With
Rugix Apps, it installs, updates, starts, stops, and removes apps. The Agent
also reconnects after it loses its connection instead of exiting, can keep its
device key in hardware such as a TPM, and reports its connection state through
`nexigon-agent status`.

The CLI selects an organization for each command, pages through large device
and version lists, and manages repository path names and checkpoint releases.

## Before Upgrading

Agent 0.7.0 replaces the update services and app command scripts that earlier
device images installed. [Upgrade to Nexigon Agent 0.7](https://docs.nexigon.dev/agent/next/upgrading)
explains how to switch Rugix Bakery, Yocto, and other images and how to roll
out the first image.

### 1. Upgrade the Hub First

Upgrade Nexigon Hub to 2026.4.0 or later. Its web interface manages the system
update and Rugix Apps integrations, and the CLI's device and version listings
require it. CLI 0.6.1 and earlier cannot list devices on Hub 2026.4.0.

### 2. Select the Organization in CLI Scripts

With a user token, the CLI's resource commands require `--organization`.
`projects create` and `repositories create` take the organization through this
option instead of as their first argument:

```shell
nexigon-cli projects create --organization <org-id> <name>
nexigon-cli repositories create --organization <org-id> <display-name>
```

Organization API tokens infer their organization, so commands that use them
need no change.

### 3. Check Scripts That Use the Agent's Commands

The Agent's `device`, `events`, and `repositories` commands now use the
connection of a running Agent through its local API. While that Agent is not
connected to Nexigon Hub, they fail instead of connecting on their own. Without
a running Agent, they connect on their own as before. The local
`repositories create` command requires `--organization <org-id>`.

### 4. Update Custom Systemd Units

Agent 0.7.0 stops gracefully on SIGTERM and interrupts an installation in
progress. The unit that earlier installers wrote gives the Agent only 5 seconds
to stop and refers to a PID file that the Agent does not write. Running the
installer again replaces the unit. In units that you maintain yourself, remove
`PIDFile` and `ExecStop` and allow 30 seconds:

```ini
[Service]
Type=exec
ExecStart=/usr/bin/nexigon-agent run
TimeoutStopSec=30
KillMode=mixed
Restart=always
RestartSec=60s
LimitNOFILE=8192
```

### 5. Adapt API Clients

The API changes in ways that affect clients that use these actions:

- The unstable `vulnerabilities_*` actions are removed. Nexigon Hub manages
  vulnerabilities in its web interface.
- `devices_SetProfiles`, `devices_UpdateProfiles`, and `devices_GetDetails`
  take or return profile assignments instead of profile IDs.
- `fleet_HaltOperation`, `fleet_ResumeOperation`,
  `fleet_ReleaseOperationStage`, and `fleet_CloseOperation` replace
  `fleet_PauseOperation` and `fleet_AdvanceOperationStage`, and the
  `DeviceTask` step is removed. Devices with Agent 0.6 keep running the
  commands of fleet operations.

## System Updates

Enable system updates with Rugix Ctrl in the Agent configuration and set the
release that the device follows:

```toml
[integrations.rugix.system-updates]
enabled = true
path = "acme/gateway-os/stable"
```

For RAUC, use `[integrations.rauc.system-updates]` instead. The
`dev.nexigon.ota.config` property of a device or its profile overrides the
path and adds policies, such as a maintenance window. The Agent reports its
progress in `dev.nexigon.ota.status`. See
[System Updates](https://docs.nexigon.dev/agent/next/concepts/system-updates).

## Rugix Apps

Enable the Rugix Apps integration, which requires Rugix Ctrl 1.4 or later:

```toml
[integrations.rugix.apps]
enabled = true
```

The `dev.nexigon.rugix-apps.config` property lists the apps that the Agent
manages and their releases. For other installed apps, the Agent offers commands
that start, stop, roll back, and remove them, so images no longer need the
command scripts of the `nexigon-rugix-apps` recipes. The
`nexigon.rugix-apps.logs` command returns the most recent log records of any
app, with Rugix Ctrl 1.4.1 or later. See
[Rugix Apps](https://docs.nexigon.dev/agent/next/concepts/rugix-apps).

## Stable Property Formats

The device properties of both integrations are stable. Later versions add only
optional fields, states, capabilities, and codes, which readers accept as
unknown values, so that an Agent can read a status that a newer Agent wrote,
for example after a device rolled back to an older system. An Agent honors a
configuration field added later only if it reports the matching capability in
its status.

Each property has a format version, which a change increments if earlier
readers must not interpret it. An Agent does not apply a configuration with a
format version that it does not support. It reports the update as blocked with
the code `unsupported-config-format` instead.

## Reconnection

The Agent reconnects to Nexigon Hub after it loses its connection. It waits
for a random delay between attempts, which grows up to 10 minutes, so that a
fleet does not reconnect at once after a Hub restart. The integrations and the
local API keep running while the Agent is disconnected. See
[Connection](https://docs.nexigon.dev/agent/next/concepts/connection).

## Hardware-Held Device Keys

The Agent can authenticate with a private key held by a TPM, a PKCS#11 token,
or the Raspberry Pi firmware. A signer script in the new `[signer]` section
provides the public key and signs the device certificate and each TLS
handshake. See [Identity](https://docs.nexigon.dev/agent/next/concepts/identity).
