# Nexigon Agent and CLI 0.6.0

Released 2026-09-18.

## Highlights

Together with Hub 2026.3.2, Agent 0.6.0 increases the default device-proxy
capacity from the legacy limit of 24 to 480 concurrent forwards. This addresses
502 responses caused by the Agent rejecting excess proxy channels during bursty
browser workloads. The Hub continues to limit older Agents to 24 forwards.

Agent 0.6.0 also introduces an explicit policy for localhost TCP forwarding,
adds optional pairing-key provisioning, and hardens remote terminal credential
handling. The CLI now supports fine-grained organization API tokens, and the
repository provides a Nix package and NixOS module for the Agent.

## Before Upgrading

### 1. Upgrade the Hub First

Upgrade to Hub 2026.3.2 before deploying Agent 0.6.0. The higher proxy capacity
takes effect when the upgraded Agent reconnects and advertises its capacity.

### 2. Configure TCP Forwarding

Agent 0.6.0 denies TCP forwarding unless the destination port is declared by an
HTTP export or explicitly allowed. Configure every required non-export port
before restarting the Agent:

```toml
[[exports]]
name = "Web UI"
protocol = "http"
port = 80

[forwarding]
enabled = true
allowed-tcp-ports = [22]
```

HTTP exports automatically allow raw TCP forwarding to their declared ports.
The additional policy above allows SSH on port 22. All destinations remain
restricted to `127.0.0.1`.

If the required ports cannot be listed in advance, allow every localhost port:

```toml
[forwarding]
enabled = true
allow-all-ports = true
```

Prefer an explicit allowlist when possible. Setting `forwarding.enabled = false`
disables only additional ports; exported ports remain accessible. Hub
permissions continue to apply.

### 3. Replace `dangerous-disable-tls`

The `dangerous-disable-tls` setting has been removed and is ignored by Agent
0.6.0. Development installations that use it must select the intended behavior
explicitly:

```toml
# Permit a hub-url using plaintext HTTP/WebSocket.
dangerous-allow-plaintext = true

# Or retain HTTPS while accepting an invalid or self-signed certificate.
dangerous-accept-invalid-certificates = true
```

These settings are independent. Enable only the behavior required by the
development environment; production connections should use validated HTTPS.

## Optional Provisioning

An unpaired Agent can accept a one-time pairing value on port 6947 when
provisioning is explicitly enabled and no static or provisioned credentials are
available.
